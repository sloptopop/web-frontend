How it works

Three engines. One referee.

sloptopop is a pipeline of engines that work on AI-generated changes. A fourth engine, the Guider, checks the output of every AI step before the next one may use it.

  1. Detector finds the slop
  2. Architect plans the fix
  3. Implementor makes it pop

Guider checks every AI step

  1. Stage 1

    Detector finds the slop

    It reads the code, and the reports of the open-source analyzers you already run, for the problems that hurt in production: database results nobody checks, swallowed errors, committed secrets, hard-coded hosts. Every finding points at a line.

  2. Stage 2

    Architect plans the fix

    It turns each finding into a plan built only from a closed set of known-safe edits. Where the context makes a change unsafe, such as client code or a deliberate comment, it plans no edit and hands you a task with a checklist instead.

  3. Stage 3

    Implementor makes it pop

    It applies the plan as small, byte-exact edits, one reviewable commit per step. Each edit names the exact code it expects to change, and nothing is written if that code has moved.

  4. Stage 4

    Guider checks every AI step

    An independent check runs on the output of the Detector, the Architect and the Implementor. Nothing moves to the next stage, or to your main branch, unless it passes.

Standards

Policy as code, not vibes

The same checks run on every repository, in every language, on every push. A missing tool fails the gate; it never skips a step.

  • 100% coverage

    Lines, branches or regions, and functions, on all product code. 99% fails.

  • Every mutant killed

    Mutation testing changes the code on purpose. If no test notices, the gate fails.

  • Zero warnings

    Strictest practical linter profile. Each suppression sits on one line, with a written reason.

  • Supply chain checked

    An SBOM, a licence allow-list, and an OSV vulnerability scan of every dependency.

  • Pinned toolchains

    Exact compiler and tool versions, verified by the gate itself.

  • Gated everywhere

    The pre-push hook and CI run the same script, so nothing reaches a remote unchecked.
