Issue type · warning

db.multi-write-no-tx

What it means. One top-level function or class method writes two or more tables through separate calls, without a transaction. Writes to history and log tables are not counted.

Why it matters. If a later write fails, the earlier ones stay. The data is left half-changed.

What to do. Put the writes in one transaction in code, through your database client (Prisma $transaction, Drizzle db.transaction, node-postgres BEGIN … COMMIT, knex transaction). supabase-js has no client-side transactions: use a server-side database client for that operation, or a database function called once with .rpc() if you choose that design. If one step calls an external system, record it through an outbox instead.
