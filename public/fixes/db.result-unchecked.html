Issue type · error for writes, warning for reads

db.result-unchecked

What it means. A query's error is never read. The result is dropped, destructured without error, or destructured with an error that the function never uses. Writes (insert, upsert, update, delete) are errors; reads (select) are warnings.

Why it matters. A failed write passes silently, and the code carries on as if the row was written. A failed read looks like "no rows".

What to do. Read error from every query result and handle it (return an error response, roll back, retry or stop), or call .throwOnError() so failures throw.

Automatic fix. Transformation for writes: unchecked writes. Coming for reads: unchecked reads.
