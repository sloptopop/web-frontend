Issue type · warning

db.sensitive-column-plaintext

What it means. A card-number, national-identifier (ssn, passport_number) or health column shows no sign of protection: no protecting name (encrypted_…, …_hash, …_token, …_last4), no encryption or hash call on it, no sloptopop:protected= column comment, no Supabase Vault reference.

Why it matters. A database leak exposes the values directly. Encryption of the storage layer cannot be seen from the repository.

What to do. Encrypt the value, keep only a hash or a token of it, or keep a truncated form. If it is protected in a way the repository cannot show, declare it with a column comment: COMMENT ON COLUMN <table>.<column> IS 'sloptopop:protected=…'.

Automatic fix. None.

Real fixes, by language

Each one is an edit sloptopop applied to a public repository, checked by the Guider, reviewed in its surrounding code, and linked to the file at the commit it was made on. Committed secret values are shortened, never republished.
