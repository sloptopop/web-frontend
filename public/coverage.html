What sloptopop checks

Every sloptopop rule is a check the Detector runs on a repository. The tables below show which controls each check evidences in six security frameworks. A mapping means that a finding, or its fix, gives evidence relevant to that item; it does not mean that passing the rule satisfies the item. Only framework identifiers are referenced; every note is our own.

SCF 2026.3

Secure Controls Framework

Rule SCF IDs and our notes
Problem reported by an open-source analyzer
analyzer.finding
  • TDA-17.1 The finding is the output of static code analysis run on the repository.
Analyzer reports not ignored by git
analyzer.reports-unignored
  • IAC-14.3 Reports can hold secret snippets, which would be committed in plain text with them.
Analyzer report that cannot be used as evidence
analyzer.unreadable-report
  • CPL-30 A report that is too large, not UTF-8 or malformed cannot serve as trustworthy evidence, so it is refused rather than half-read.
No CI workflow running the quality gate
ci.missing
  • CHG-07 CI tests and validates every change before it is merged or released.
  • TDA-05.3 A CI pipeline is the shared, automated part of the development toolchain.
  • TDA-17 CI is where security and quality testing runs consistently throughout development.
CI checks configured so they cannot fail the build
ci.nonblocking-checks
  • CHG-07 A check that cannot fail does not actually validate the change.
  • TDA-17 Testing exists on paper but its results do not gate anything.
Hard-coded private IP or localhost URL in source
config.hardcoded-host
  • CFG-02 Environment endpoints belong in managed configuration, not in compiled source.
  • TDA-15.1 Development or internal addresses in shipped code blur the line between environments.
Lines that no test executes
coverage.uncovered
  • CHG-07 Changed code that no test runs has not been validated before release.
  • TDA-14 Uncovered lines are product code that testing never reviewed.
Errors caught and silently discarded
errors.swallowed
  • SEA-15 Discarding an error lets execution continue as if it succeeded, i.e. it fails open.
  • TDA-12.1 An empty handler is the absence of error handling.
No pre-push hook running the quality gate
hook.missing
  • CHG-07 The hook tests and validates a change locally before it leaves the developer's machine.
  • TDA-17 A pre-push gate puts automated checks at the earliest point of the development cycle.
Repository has no licence file
licence.missing
  • AST-13 Without a licence, the terms under which the software may be used or redistributed are undefined.
Dependency lockfile is missing
lockfile.missing
  • AST-14 A lockfile records exactly which third-party components, from which source, end up in the build.
  • TDA-21.4 Resolved dependency versions are the raw input for an accurate software bill of materials.
Secret material committed to the repository
secrets.committed
  • CRY-10 Committed private keys are keys outside any managed key lifecycle.
  • IAC-14.2 Credentials in version control are exposed to everyone with repository access, now and in history.
  • IAC-14.3 This is exactly a static credential embedded in plain text in code or configuration.
Secret found in a commit of the repository's history
secrets.in-history
  • IAC-14.1 A secret that reached history must be treated as compromised and changed, even if the file no longer holds it.
  • IAC-14.2 Every clone keeps the commit, so the credential stays exposed to everyone with repository access.
  • IAC-14.3 A static credential was embedded in plain text in code or configuration when it was committed.
No enforced test-coverage threshold
tests.no-coverage-floor
  • TDA-17 Without a floor, the amount of code actually exercised by tests can drop unnoticed.
TLS certificate verification turned off
tls.verification-disabled
  • CRY-05 Encryption without peer verification does not protect data in transit from an interceptor.
  • CRY-06 Without certificate checks, traffic can be modified by whoever terminates the connection.
Build toolchain version is not pinned
toolchain.unpinned
  • TDA-05.3 The compiler/interpreter version is part of the supporting toolchain and should be fixed, not floating.
  • TDA-20 A toolchain pin file puts the build tools under the developer's configuration control.
Static type checking switched off
types.disabled
  • TDA-17.1 The type checker is a built-in static analysis tool; switching it off removes that analysis.

Control identifiers from the Secure Controls Framework (SCF) 2026.3, (c) SCF Council, licensed under CC BY-ND 4.0. Only control IDs are referenced; no SCF text is reproduced or modified. The notes are sloptopop's own.

NIS2 Directive (EU) 2022/2555; Implementing Regulation (EU) 2024/2690

NIS2: Directive (EU) 2022/2555 and Commission Implementing Regulation (EU) 2024/2690

Rule NIS2 IDs and our notes
No CI workflow running the quality gate
ci.missing
  • 2024/2690 Annex 6.2.2(d) CI is a security testing process embedded in the development life cycle.
  • 2024/2690 Annex 6.4.2 CI provides the record that a change was tested before it was implemented.
  • Art. 21(2)(e) Automated verification of every change is part of secure development and maintenance.
CI checks configured so they cannot fail the build
ci.nonblocking-checks
  • 2024/2690 Annex 6.4.2 Changes can be implemented even when their tests fail.
  • 2024/2690 Annex 6.5.2(d) Critical findings from security steps produce no mandatory action.
  • Art. 21(2)(e) Checks that never block weaken security in development.
  • Art. 21(2)(f) A non-blocking check is a control whose effectiveness is not enforced.
Hard-coded private IP or localhost URL in source
config.hardcoded-host
  • 2024/2690 Annex 6.3.1 Endpoints baked into code escape the documented, managed configuration.
  • Art. 21(2)(e) Keeping configuration out of code is part of secure development and maintenance.
Lines that no test executes
coverage.uncovered
  • 2024/2690 Annex 6.2.2(d) Measured coverage shows where the testing step leaves code unchecked.
  • Art. 21(2)(e) Untested code weakens security in development.
  • Art. 21(2)(f) Line coverage is a measurable indicator of whether testing is effective.
Errors caught and silently discarded
errors.swallowed
  • 2024/2690 Annex 6.2.2(b) Handling every error is a basic secure-coding principle.
  • Art. 21(2)(e) Handling errors properly is part of secure development.
No pre-push hook running the quality gate
hook.missing
  • 2024/2690 Annex 6.2.2(d) The hook is one stage of the security testing process within the development life cycle.
  • Art. 21(2)(e) Automated checks before code is shared are part of security in development.
Dependency lockfile is missing
lockfile.missing
  • 2024/2690 Annex 6.1.2(c) A lockfile is machine-readable evidence of the software components a product is built from.
  • Art. 21(2)(e) Knowing and controlling the components of developed software is part of secure development and maintenance.
Secret material committed to the repository
secrets.committed
  • 2024/2690 Annex 11.6.2(b) Secret authentication information in code is not handled confidentially.
  • 2024/2690 Annex 9.2(c)(iv) Keys stored in a repository are not stored according to a key-management method.
  • Art. 21(2)(h) Committed private keys break the entity's cryptographic key handling.
  • Art. 21(2)(i) Leaked credentials undermine access control.
Secret found in a commit of the repository's history
secrets.in-history
  • 2024/2690 Annex 11.6.2(b) Secret authentication information kept in history is not handled confidentially.
  • 2024/2690 Annex 9.2(c)(iv) A key that was committed was not stored according to a key-management method.
  • Art. 21(2)(h) A private key in history breaks the entity's cryptographic key handling until it is replaced.
  • Art. 21(2)(i) A leaked credential that is still valid undermines access control.
No enforced test-coverage threshold
tests.no-coverage-floor
  • 2024/2690 Annex 6.2.2(d) A threshold turns the testing process into an enforced, checkable step.
  • Art. 21(2)(e) Measurable testing is part of secure development.
  • Art. 21(2)(f) A coverage floor is a measurable indicator of whether testing is effective.
TLS certificate verification turned off
tls.verification-disabled
  • 2024/2690 Annex 6.7.2(i) A channel without endpoint verification does not give assured identification of the peer.
  • 2024/2690 Annex 9.2(b) Turning off verification is a protocol usage practice that should not be approved.
  • Art. 21(2)(h) Disabling verification defeats the purpose of the entity's use of cryptography.
Build toolchain version is not pinned
toolchain.unpinned
  • 2024/2690 Annex 6.2.2(c) A pinned toolchain is a concrete, checkable requirement on the development environment.
  • Art. 21(2)(e) Controlling the build environment is part of security in system development.
Static type checking switched off
types.disabled
  • 2024/2690 Annex 6.2.2(b) Strict typing is a secure-coding principle the toolchain can enforce.
  • Art. 21(2)(e) Using available compiler/type safety is part of secure development.

Article and annex point references from Directive (EU) 2022/2555 (Art. 21(2)) and Commission Implementing Regulation (EU) 2024/2690 (Annex; https://eur-lex.europa.eu/eli/reg_impl/2024/2690/oj), source EUR-Lex, (c) European Union; reuse authorised under Commission Decision 2011/833/EU. No pre-push hook running the quality gate

  • PW.5.1 The development environment enforces the agreed coding checks automatically.

lockfile.missing
  • PS.3.2 Exact dependency versions are the provenance data an SBOM is built from.
  • PW.4.4 Components can only be checked for known vulnerabilities over time if the exact versions are known.

secrets.committed
  • PW.7.2 Secret scanning is automated code analysis that flags an unsafe practice as code is checked in.

secrets.in-history
  • PW.7.2 Scanning the history for secrets is automated analysis that flags an unsafe practice already checked in.
No enforced test-coverage threshold
tests.no-coverage-floor

Static type checking switched off
types.disabled
  • PW.5.1 Using strict type checking is a language-appropriate secure coding practice.
  • PW.6.2 The compiler/interpreter feature that catches unsafe code is not configured on.
