Where the lists come from

  1. Scraped, not written

    A scraper reads each framework from the publisher's own document. Nobody types a list and no model recalls one.

  2. Checked for gaps

    Every point must occur in the document, numbering may not skip unless the document says so, and a second count of the raw document must agree.

  3. Ruled on, point by point

    A status comes from a recorded decision that a named sloptopop rule gives evidence for that point. Anything else stays coming soon.

  4. Not a certificate

    A check shows a breach in code. No tool can certify a framework, and many points are about your organisation rather than your code.

Evidence every run produces

  • Findings

    Every finding names its rule, file and line, so an auditor can check it at the commit it was found on.

  • The plan

    Each finding becomes a step built only from a closed set of known-safe edits, or a task with a checklist and the recorded reason why no edit was made.

  • Exact edits

    Every applied edit is a byte span with the hash of the code it expects, in its own reviewable commit; nothing is written if the code has moved.

  • Verification

    After the edits: sloptopop checks again, the type checker or syntax check runs on the touched files, and the secret scan runs before and after.
