OWASP Top 10

OWASP Top 10:2025 · current · voluntary · official text (free)

Applies to: Nobody is bound; the list classifies web application security risks.

  • 10 points
  • 1 we fix
  • 8 we detect
  • 1 coming soon
We fix
sloptopop finds evidence of a breach of this point in your code, and at least one of those checks has an automatic fix that has passed review on real code.
We detect
sloptopop finds evidence of a breach of this point in your code, and you fix it.
Coming soon
sloptopop does not check this point yet.

A check shows a breach in code; it does not certify that a point is met. List scraped from the publisher's document on 2026-11-01. A point here means: The ten risk categories of the 2025 edition (they have no numbered level below them).

PointWhat it saysStatussloptopop's checks
A01:2025 Broken Access ControlUsers must only act within their permissions; access restrictions must be enforced on the server side. We detect

arch.privileged-key-client-sideA privileged key in client code lets any user act beyond their role; access control is not enforced in trusted server-side code.

db.rls-missingRows are not restricted by owner or role, so access is not denied by default (CWE-862 is mapped here).
A02:2025 Security MisconfigurationSystems, frameworks and cloud settings must be hardened, with no insecure defaults or unneeded features. We detect

secrets.insecure-defaultA sample secret left as the default is a default credential that stays unchanged in deployments.
A03:2025 Software Supply Chain FailuresDependencies, build processes and distribution must be trustworthy and controlled against supply chain compromise. We detect

deps.unpinnedThe dependency version floats instead of being deliberately chosen and tracked.

lockfile.missingWithout a lockfile the exact versions of direct and transitive components are not tracked.

toolchain.unpinnedThe runtime or build tool version floats, so the toolchain is not a tracked, deliberately chosen component.
A04:2025 Cryptographic FailuresSensitive data must be protected with sound cryptography in transit and at rest. We detect

db.sensitive-auth-data-storedCard codes, track or PIN data are kept although the category says not to store sensitive data unnecessarily.

db.sensitive-column-plaintextCard, identity or health data at rest show no encryption, which this category asks for all sensitive data.

tls.verification-disabledThe category asks whether the server certificate and trust chain are validated; here they are not.
A05:2025 InjectionUntrusted input must not be interpreted as commands or queries; use safe, parameterised interfaces. We detect

agent.as09.insecure-defaultA string-built query or command is direct evidence of the core flaw here, though weak hash and CORS findings of this rule are not.
A06:2025 Insecure DesignSecurity must be designed in, using threat modelling, secure patterns and reference architectures. We detect

arch.threat-model-missingNo threat model is the missing secure-design activity this category names as a root cause.

db.sensitive-column-plaintextCleartext storage of sensitive information (CWE-312) is mapped to this category.

db.transition-unguardedA state change that skips the current-state check breaks the designed workflow (CWE-841 is mapped here).

db.version-uncheckedIgnoring the version column allows lost updates, a race condition (CWE-362 is mapped to this category).
A07:2025 Authentication FailuresIdentity confirmation, credential handling and session management must resist attacks such as guessing and hijacking. We detect

secrets.committedHard-coded credentials (CWE-798) are mapped to this category.

secrets.in-historyA hard-coded credential (CWE-798) stays in the repository history.

secrets.insecure-defaultShipping with default credentials (CWE-1392) is listed in this category.

tls.verification-disabledImproper certificate validation (CWE-295) is mapped to this category.
A08:2025 Software or Data Integrity FailuresCode, updates and data must be protected from untrusted or unverified modification. Coming soon
A09:2025 Security Logging and Alerting FailuresSecurity-relevant events must be logged, retained intact and alerted on to enable detection. We detect

db.audit-table-mutableAudit records the application can change lack the tamper protection (append-only tables) the category calls for.

db.audit-trail-missingChanges to business or sensitive records leave no audit trail (CWE-778 is mapped to this category).

db.cascade-deletes-historyA delete cascades into the audit trail, so the trail is not protected against deletion.
A10:2025 Mishandling of Exceptional ConditionsErrors and abnormal conditions must be prevented, detected and handled safely rather than ignored. We fix

agent.as03.broad-catchA catch-all handler shows errors are not treated by type, a recognised weakness in this category (generic catch, CWE-396).

agent.as03.swallowed-errorA discarded or defaulted error shows the code hides a failure rather than responding to it, directly evidencing this category.

db.multi-write-no-txA multi-table write without a transaction cannot roll back every part on failure, the fail-closed handling the category asks for.

db.result-unchecked auto-fix: writes, in JavaScript and TypeScript with supabase-jsThe query error is never read, an unchecked return value (CWE-252 is mapped to this category).

errors.swallowedAn error is detected and then discarded (CWE-390 is mapped to this category).
